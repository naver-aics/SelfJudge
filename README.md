# SelfJudge: Faster Speculative Decoding via Self-Supervised Judge Verification

Official PyTorch implementation of **SelfJudge** (ICML 2026).

[![arXiv](https://img.shields.io/badge/arXiv-2510.02329-red)](https://arxiv.org/abs/2510.02329)


## Overview

SelfJudge speeds up speculative decoding by relaxing exact-match verification. When the
draft and target models disagree on a token, a lightweight judge head on the target
model's hidden state decides whether the mismatch actually matters; unimportant
mismatches are accepted rather than rejected, raising the acceptance rate without
changing the target model.

The judge is trained with a self-supervised signal: each mismatch is scored by the joint
log-probability of the following tokens under the target model, with no task-specific
answer checking. This yields cleaner "important token" labels and extends naturally to
open-ended instruction data, where no ground-truth answer exists.

This code base builds on [AutoJudge](https://arxiv.org/abs/2504.20039), which introduced
judge-based verification using task-accuracy labels.


## Getting started

```bash
pip install -r requirements.txt
```

The examples below use the Llama draft/target pair (`meta-llama/Llama-3.2-1B-Instruct` /
`meta-llama/Llama-3.1-8B-Instruct`). Qwen models (`Qwen/Qwen2.5-0.5B-Instruct` /
`Qwen/Qwen2.5-7B-Instruct`) are also supported — just pass them via `--draft_model` /
`--target_model`. A local path works too.


## Pipeline

This release is set up to run on two benchmarks: **GSM8K** and **LiveCodeBench (LCB)**.
The full pipeline has four stages. Convenience wrappers live in `scripts/`.

### 1. Mine important tokens (SelfJudge labeling)

Score draft/target mismatches by the next-few-token likelihood difference.

```bash
# GSM8K  (see scripts/compare_token.sh)
CUDA_VISIBLE_DEVICES=0 python3 src/compare_important_tokens_gsm8k.py \
    --draft_model  meta-llama/Llama-3.2-1B-Instruct \
    --target_model meta-llama/Llama-3.1-8B-Instruct \
    --gsm8k_train_path data/gsm8k/train.jsonl \
    --num_next_token 20 \
    --output_folder compare \
    --output_file important_tokens--model-selfjudge-500_samples

# LiveCodeBench  (see scripts/compare_token_lcb.sh)
python3 src/compare_important_tokens_lcb.py --n_tasks 220 --num_next_token 20 ...
```

For the original AutoJudge single-token labeling use `src/find_important_tokens.py`
(`scripts/find_important_tokens_gsm8k.sh`) or `src/find_important_tokens_lcb.py`
(`scripts/find_important_tokens_lcb.sh`).

> **Want to skip this stage?** Mining runs both models over the full training set and is by
> far the most expensive step. The important-token `.pt` files we mined for the paper are
> available for download at **[[LINK](https://drive.google.com/drive/folders/1BlUFK6sx0X664lsdeCAa67f4DeR0fuCx?hl=ko)]**, covering the GSM8K, LiveCodeBench and Dolly-15k
> splits for both the Llama and Qwen draft/target pairs. They are not part of the repo
> checkout (`*.pt` is gitignored). They already contain the extracted hidden states and the
> likelihood scores the notebooks threshold into labels, so stages 1–2 can be skipped — go
> straight to stage 3. Pick the file matching the draft/target pair you intend to use;
> features extracted with the Llama pair do not transfer to the Qwen pair, and vice versa.
>
> Each record also keeps the source prompt and the full model generation (as text and token
> ids), so the files can be re-processed with stage 2. The Llama-pair files therefore contain
> text generated by `Llama-3.1-8B-Instruct` (with `Llama-3.2-1B-Instruct` drafts) as well as
> its hidden states, and are subject to the Llama 3.1 / 3.2 Community Licenses. Prompts come
> from GSM8K, LiveCodeBench and Dolly-15k and keep their own licenses — see
> [`NOTICE_models`](NOTICE_models) and the `NOTICE_dataset.txt` shipped with the download.

### 2. Extract hidden states

```bash
# see scripts/calc_hiddens.sh
CUDA_VISIBLE_DEVICES=0 python src/calc_hiddens.py \
    --draft_model  meta-llama/Llama-3.2-1B-Instruct \
    --target_model meta-llama/Llama-3.1-8B-Instruct \
    --data_file   compare/important_tokens--model-selfjudge-500_samples.pt \
    --output_path compare/important_tokens--model-selfjudge-500_samples-hiddens
```

### 3. Train the classifier

Open the training notebooks in `notebooks/`. Each fits a `StandardScaler` +
`LogisticRegression` head on the extracted hidden states and saves a `.pkl`:

- `train_selfjudge-fulldata.ipynb` — SelfJudge head
- `train_autojudge-fulldata.ipynb` — AutoJudge baseline head

### 4. Evaluation (judge decoding)

Run judge-gated speculative decoding with a trained head. Two benchmarks are supported.
Pass the SelfJudge head via `--head_path` — e.g. the next-few-token (`num20`) head
`verifier_general/Llama-3.1-8B-self-logistic-num20.pkl` (use `qwen2.5-7b-self-logistic-num20.pkl`
for the Qwen pair):

```bash
# GSM8K
python eval/run_inference_task_gsm8k.py \
    --draft_model meta-llama/Llama-3.2-1B-Instruct \
    --target_model meta-llama/Llama-3.1-8B-Instruct \
    --head_path verifier_general/Llama-3.1-8B-self-logistic-num20.pkl --head_threshold <t> \
    --gsm8k_test_path data/gsm8k/test.jsonl

# LiveCodeBench
python eval/run_inference_task_lcb.py \
    --draft_model meta-llama/Llama-3.2-1B-Instruct \
    --target_model meta-llama/Llama-3.1-8B-Instruct \
    --head_path verifier_general/Llama-3.1-8B-self-logistic-num20.pkl --head_threshold <t>
```

Top-k acceptance baselines: `run_inference_topk_baseline_task.py` (GSM8K) /
`run_inference_lcb_topk_baseline_task.py` (LCB). LiveCodeBench cross-validation folds:
`run_inference_task_lcb_folds.py`.

The runners are single-GPU. For multiple GPUs, split the task range across processes
(`CUDA_VISIBLE_DEVICES=0 ... --start 0 --end 500 &`, `CUDA_VISIBLE_DEVICES=1 ... --start
500 --end 1000 &`), or drive them with an external multi-GPU task launcher. Workers
sharing a `--save_folder` skip tasks that already have a result file.
